Warum Ihr Proxy blockiert wird: sieben echte Ursachen

„Meine Proxys sind blockiert“ ist ein Symptom, keine Diagnose. Blockierungen entstehen in Schichten — und die Schicht, die Sie zuerst verdächtigen, ist selten die, die versagt.

1. Rate und Parallelität

Die häufigste und am meisten übersehene Ursache. Zehn Anfragen pro Sekunde von einer Adresse reichen für eine Limitierung — auch bei einwandfreier Residential-IP. Beginnen die Fehler nach N Anfragen und nicht nach einem geografischen Muster, ist es diese Schicht.

Abhilfe: Parallelität senken, auf mehr Adressen verteilen, Zufall in die Pausen bringen. Feste Intervalle sind selbst ein Muster.

2. Verhalten, das kein Mensch erzeugt

Identische Header, keine Cookies, kein Referer, perfekte Reihenfolge, maschinelle Intervalle. Der Detektor braucht Ihre IP nicht — ihm genügt Ihr Anfrageprotokoll.

3. ASN-Reputation — hier verliert das Datacenter

Die Regel lautet meist nicht „diese IP ist gesperrt“, sondern „dieses ganze Netz gehört einem Hoster“. Das kann jede Website nachschlagen. Es ist die einzige Ursache, die eine andere Adressklasse wirklich behebt.

Abhilfe: auf ISP/statisches Residential oder Residential wechseln — die Mittelstufe reicht oft. Siehe welchen Proxy-Typ Sie brauchen.

4. Fingerprint im Widerspruch zu den Headern

Sie geben sich als Chrome unter Windows aus, aber TLS-Handshake und Browser-Fingerprint sagen Python requests. Alles andere kann perfekt sein — das allein kostet Sie eine Challenge.

5. Geerbte Historie in geteilten Pools

In geteilten Residential-Netzen erben Sie nicht nur die Adresse, sondern was andere damit gemacht haben. Zwei identische Setups können sich allein deshalb unterschiedlich verhalten.

6. Ihre eigene Wiederholungslogik

Eine naive Wiederholungsschleife vervielfacht die Last genau dann, wenn das Ziel schon unzufrieden ist. Fünf sofortige Wiederholungen machen aus einer weichen Drossel eine harte Sperre.

Abhilfe: exponentielles Backoff mit Jitter, Circuit Breaker pro Adresse, Obergrenze pro URL. 429 und 503 sind Signale, keine Zufallsfehler.

7. Parallelität gegen eine Session, die konsistent bleiben muss

Umfasst ein Ablauf mehrere Anfragen, zerlegt Parallelisierung über verschiedene Ausgangsadressen die Session — und die Seite antwortet, als täten Sie etwas Feindseliges, weil Sie es aus ihrer Sicht tun.

Abhilfe: eine Adresse pro Session fixieren und die Anfragen darin sequenziell halten. Dafür gibt es Sticky Sessions.

Bevor Sie einen größeren Pool kaufen

Fahren Sie den Test aus Proxy vor dem Kauf testen. Liegt Ihre Erfolgsquote zwischen 70 % und 95 %, ist es fast immer Konfiguration: Ein teurerer Pool verdeckt das eine Woche und scheitert dann genauso.

Brauchen Sie eine andere Adressklasse, um die ASN-Hypothese zu prüfen, ist das der einzige Fall, in dem der Kauf das Experiment ist. IPRoyal etwa bietet Datacenter-, ISP- und Residential-Pools unter einem Konto — so lässt sich der Vergleich ohne drei Verträge ziehen.

Kurzfassung

  • Blockierungen sind geschichtet: erst Rate, Verhalten und Fingerprint prüfen, dann den Pool.
  • ASN-Reputation ist die einzige Ursache, die eine andere Adressklasse behebt.
  • Statuscodes getrennt protokollieren, damit jede Schicht ihre eigene Antwort bekommt.
  • Erst Wiederholungen und Sessions reparieren — das ist kostenlos und meist das Problem.

Letzte Prüfung: September 2026. Scraping-Regeln unterscheiden sich je nach Website und Rechtsraum — beachten Sie Nutzungsbedingungen und geltendes Recht.
